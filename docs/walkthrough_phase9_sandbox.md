# AutoPatch — Phase 9: Real Docker Sandbox & Hardened Validation Walkthrough

## 1. Executive Summary

Phase 9 implements a real, production-ready **Docker-based Sandbox** (`DockerSandboxExecutor`) and comprehensive security hardening across AutoPatch's validation pipeline. Candidate patches generated by the AI are treated as untrusted code proposals that must execute under strict security isolation, network barriers, resource constraints, and repository immutability verification before validation verdicts are rendered.

The architecture strictly adheres to a **fail-closed** model: if Docker isolation is configured and unavailable, validation halts with an explicit error rather than silently degrading to insecure execution.

## 2. Security Architecture & Threat Model

```text
Target Repository (Host)
          │
          ▼
1. Initial SHA-256 Hash Tree Calculation (Pre-validation host state snapshot)
          │
          ▼
2. Isolated Temporary Workspace (backend/tools/workspace.py)
   • Pristine copy created in OS temporary directory
   • Symlink directory and file escape guards (rejects links resolving outside repo)
   • Handles circular symlinks, broken symlinks, and Windows readonly permissions
          │
          ▼
3. Atomic Patch Application (backend/tools/patch_applier.py)
   • Strict validation: rejects traversal (../), encoded traversal (%2e%2e), Windows drive paths (C:),
     UNC paths (\\\\), /dev/null, binary diffs, and test file modifications
   • Requires --- and +++ headers to match the same existing target file
   • Exact whitespace and indentation matching (no relaxed stripping)
   • File- and workspace-level atomicity: staged in memory; zero disk writes if any hunk fails
          │
          ▼
4. Docker Sandbox Execution (backend/tools/sandbox.py)
   • Invokes: docker run --rm
   • --network none (Strict network isolation: zero internet, zero localhost, zero LAN)
   • --user 10001:10001 (Unprivileged non-root user execution)
   • --cap-drop=ALL (Drops all Linux capabilities)
   • --security-opt no-new-privileges (Prevents privilege escalation)
   • -v <temp_ws>:/workspace:rw (Mounts ONLY the ephemeral temporary directory)
   • Resource constraints: --memory 512m, --cpus 1.0, --pids-limit 100
   • Absolute ban on --privileged, /var/run/docker.sock, and host repository mounts
          │
          ├──> 4a. Syntax / Bytecode Check (python -m compileall -q .)
          │
          ├──> 4b. Controlled Test Runner (python -m pytest -q)
          │         • Summarizes passed, failed, skipped, and total tests
          │         • Distinguishes collection errors from ordinary test failures
          │
          └──> 4c. Static Security Re-Scan (Bandit & Semgrep on isolated workspace)
          │
          ▼
5. Differential Security Analysis
   • Proximity and rule ID matching against baseline scan
   • Categorization: resolved vs remaining vs newly introduced findings
          │
          ▼
6. Host Immutability Verification
   • Post-validation SHA-256 tree calculation
   • Verifies zero bytes altered in target repository; aborts if hash mismatch
          │
          ▼
7. Full Evidence Persistence & API (backend/database/models.py & backend/api/routes/validation.py)
   • Persists syntax_check_passed, tests_run, test_exit_code, test_stdout, test_stderr,
     new_findings (JSON), duration, and sandbox_type
   • GET endpoints return exact stored evidence without manufactured defaults
```

## 3. Docker Container Specifications (`docker/validation/Dockerfile`)

```dockerfile
FROM python:3.11-slim

ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1

RUN groupadd -g 10001 validator && \
    useradd -u 10001 -g validator -m -s /bin/bash validator

RUN pip install --no-cache-dir \
    pytest==7.4.3 \
    bandit==1.7.5 \
    semgrep==1.50.0

WORKDIR /workspace
USER 10001:10001
CMD ["python", "-m", "pytest", "-q"]
```

### Build Instructions
```powershell
docker build -t autopatch-validator:latest -f docker/validation/Dockerfile .
```

### Runtime Security Guarantees
1. **Network Isolation**: Always invoked with `--network none`. Candidate patches cannot exfiltrate code, contact command-and-control servers, or connect to internal cloud metadata services (e.g. `169.254.169.254`).
2. **Filesystem Isolation**: Mounts strictly map the ephemeral temporary workspace to `/workspace`. Host root filesystems and the original repository are completely invisible inside the container.
3. **Privilege Demotion**: The container runs under UID `10001:10001` with `--cap-drop=ALL` and `--security-opt no-new-privileges`. Even if a candidate patch contains an exploit, it cannot acquire root or escape namespace boundaries.
4. **Deterministic Timeout & Cleanup**: If container execution exceeds `DOCKER_TIMEOUT`, the executor issues `docker kill <container_name>`, releases workspace locks, and captures timeout diagnostics.

## 4. Configuration Reference (`backend/config.py`)

| Setting | Default | Purpose |
| :--- | :--- | :--- |
| `DOCKER_ENABLED` | `False` | When `True`, mandates Docker sandbox execution. Fails closed if Docker is down. |
| `DOCKER_IMAGE` | `autopatch-validator:latest` | Target Docker image for validation. |
| `DOCKER_MEMORY_LIMIT` | `512m` | Maximum container RAM allocation. |
| `DOCKER_CPU_LIMIT` | `1.0` | Maximum container CPU quota. |
| `DOCKER_PIDS_LIMIT` | `100` | Process/fork bomb mitigation limit. |
| `DOCKER_TIMEOUT` | `60` | Container execution timeout in seconds. |
| `ALLOW_LOCAL_FALLBACK` | `True` | Permitted in development when `DOCKER_ENABLED=False`. Reports `sandbox_type="local_workspace_dev_fallback"`. |
